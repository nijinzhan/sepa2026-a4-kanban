## 3. 配置与真实模型

将 `config.example.json` 另存为 `config.local.json`，填写实际服务地址、引擎代码、模型名称及版本，指定实际模型和 tokens 文件。样例中的地址、代码和模型标签仅演示配置格式，不表示团队已有对应服务或模型部署。

相对模型路径以配置文件所在目录解析。`vad`指定适用于16kHz的 Silero ONNX；`asr`指定 SenseVoice ONNX及对应tokens。当前适配CPU；`language=en`为样例中的ATC英语配置。受控配置参数才传给推理库，快照元数据不透传为推理参数。

模型适配遵循[SenseVoice 官方 Python API](https://k2-fsa.github.io/sherpa/onnx/sense-voice/python-api.html)和[官方 VAD＋离线 ASR 示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/vad-with-non-streaming-asr.py)。代码不会自动下载模型，也没有用固定文本或简单能量阈值替代实际推理的回退。

任务创建前查询启用引擎，核对引擎代码；登记中非空的模型名/版本与本地清单冲突时停止。实际文件SHA256由程序计算，写入快照；更改模型文件后不能继续按旧快照执行。

先检查本地文件清单，再用真实音频检查推理：

```powershell
.\.venv\Scripts\python.exe -m a4_speech --config config.local.json check-model
.\.venv\Scripts\python.exe -m a4_speech --config config.local.json check-model --audio 'D:\实际样例路径\sample.wav'
```

第一条只检查模型配置与文件身份，返回 `inferenceChecked=false`，不能据此认定模型可推理。第二条运行真实VAD，存在有效语音时再运行真实ASR；静音样例会显示 `asrInferenceChecked=false`。

2026-10-17 已在本机完成实际模型配置和推理验证，使用上游明确标注的 Silero VAD v5.0 与 sherpa-onnx 发布的 SenseVoice int8 2024-07-17 模型包。本机 `config.local.json` 已填写实际模型路径；其中服务地址仍为样例地址，引擎代码也尚未与团队登记联调。文件来源、哈希、实际输出、复现命令及质量限制见[真实模型验证记录](真实模型验证记录.md)。

## 4. 与团队接口运行

凭据从配置指定的环境变量读取，默认为 `A4_API_KEY`。在当前终端设置团队实际提供的服务凭据后执行；配置文件和命令输出不保存凭据。

```powershell
.\.venv\Scripts\python.exe -m a4_speech --config config.local.json transcribe --recording-id '实际录音UUID' --idempotency-key '唯一请求标识'
.\.venv\Scripts\python.exe -m a4_speech --config config.local.json read --transcript-id '实际文本UUID' --job-id '对应识别任务UUID'
```

转写依次读取录音及内容、检测语音、核对已有段并登记新段、读回段ID、检查已有文本、建立含固定目标和快照的任务、逐段识别、一次提交全部文本、读回任务与文本。仅最后核对通过才输出 `status=succeeded`、`saveConfirmed=true`。

读取命令可省略 `--job-id`，此时只读取并核对文本、录音和时间，返回 `historyStatus=job_context_required`。不通过录音ID猜测所属任务。

程序标准输出为JSON，成功退出0，业务、接口、配置或模型输入错误退出2。日志写到标准错误，包含任务、计数、结果和错误代码；需要留存运行证据时可分别保存两路输出。错误输出不包含服务响应全文和原始凭据。

## 5. 关键规则与实现边界

### 分段及时间

预查调用 `onlySpeech=false`，同时考虑非语音段冲突；当前契约为非分页列表，兼容带完整分页元数据的扩展响应。完全相同的语音段复用现有ID和序号；同起点异终点或实际重叠均停止。相邻首尾相接合法。只新增不存在的段，固定 `replaceAll=false`。409或传输不明先读回，不盲目重发。

下载后的实际样本时长与录音整数毫秒允许最多50ms的编码/元数据差异；此容忍量不是时间平移。段本身仍必须在录音范围内。仅当样本时长向上取整比录音末尾多1ms时，允许将这一量化尾点收回录音末尾，任意更大越界不会被裁剪掩盖。

绝对时间按录音带时区起点加相对毫秒核对，不再次叠加偏移。不输出推测的VAD得分或ASR置信度。

### 计数、发布与重复执行

- 无语音返回 `NO_SPEECH`，不写空段、不建空ASR任务。
- 已处理数包括已结束的成功/失败ASR尝试；失败数为其中失败项。第2段失败时计数为2/1，第3段不执行。
- 模型初始化在建ASR任务前独立完成，初始化失败不虚报为片段失败。
- 任一片段失败即停止，只回写失败状态和计数，不提交已经识别出的部分文本。模型创建后变化也回写失败。
- 全部识别成功但保存未确认时返回 `SAVE_UNCONFIRMED`，保留实际识别计数，不把存储错误计入ASR失败数；完成请求只发一次。
- 已存在文本、人工修改结果或queued/processing片段会阻止新一轮转写，避免覆盖。已有结果通过读取入口查看。

单任务受公共 `segmentIds` 上限约束，最多500段；更多目标应由编排功能组织独立任务。本次没有擅自扩展公共契约。

本地 `outputs/requests/` 保存请求哈希、录音ID和任务ID收据，只用于阻止本机盲目重放，不存第二套业务文本。相同键已成功时读回已有结果；未完成、结果不明或收据损坏时停止，不自动接管任务。相同幂等键限64个可打印ASCII字符；新的人工尝试使用新的键，并先核查已有任务与结果。

该收据不是分布式锁。不同机器/不同入口并发、公共调度领取与租约，需要团队服务提供共同约束。当前代码用于人工单执行者调用，不启动后台扫描或工作队列。

### 历史模型

创建时快照位于 `params.a4_10_20.executionSnapshot`；完成时实际快照位于 `stats.a4_10_20.executionSnapshot`。个人扩展JSON还保存固定目标清单、目标录音、本次段数以及原文摘要 `transcriptDigests`。摘要绑定录音、片段、相对时间和原始文本，校验人工修改后的当前文本时仍保留原文含义。

历史读取要求明确任务已经成功、目标关联匹配、原文摘要匹配、创建与执行快照一致。没有快照返回 `not_recorded`；快照或证据不完整返回 `source_unverified`。读取旧结果不查询当前引擎版本来冒充历史。

当前公共文本详情没有 `jobId`，所以即便内容核对通过，仍返回 `sourceJobLinkVerified=false`：已核对显式任务目标及原文摘要，尚不能用公开响应独立证明数据库的文本所属任务外键。此项和完成接口的原子性、人工编辑并发保护，须在真实服务联调中核实。客户端预查和模拟测试不能替代服务端事务或锁。
