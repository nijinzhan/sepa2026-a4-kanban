## 3. 配置与真实模型

将 `config.example.json` 另存为 `config.local.json`，把样例值替换为团队实际服务地址、引擎代码、模型名称及版本，并指定本地模型和 tokens 文件。

相对模型路径以配置文件所在目录解析。`vad`指定适用于16kHz的 Silero ONNX；`asr`指定 SenseVoice ONNX及对应tokens。当前适配CPU；`language=en`为样例中的ATC英语配置。受控配置参数才传给推理库，快照元数据不透传为推理参数。

模型适配遵循[SenseVoice 官方 Python API](https://k2-fsa.github.io/sherpa/onnx/sense-voice/python-api.html)和[官方 VAD＋离线 ASR 示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/vad-with-non-streaming-asr.py)，模型文件需手动准备。

任务创建前查询启用引擎，核对引擎代码；登记中非空的模型名/版本与本地清单冲突时停止。实际文件SHA256由程序计算，写入快照；更改模型文件后不能继续按旧快照执行。

先检查本地文件清单，再用真实音频检查推理：

```powershell
.\.venv\Scripts\python.exe -m a4_speech --config config.local.json check-model
.\.venv\Scripts\python.exe -m a4_speech --config config.local.json check-model --audio 'D:\实际样例路径\sample.wav'
```

第一条检查模型配置与文件身份，返回 `inferenceChecked=false`。第二条执行 VAD，存在有效语音时再执行 ASR；静音样例返回 `asrInferenceChecked=false`。

2026-10-17 已在本机完成模型配置和推理验证，使用 Silero VAD v5.0 与 sherpa-onnx 发布的 SenseVoice int8 2024-07-17 模型包。本机 `config.local.json` 已填写实际模型路径，服务地址和引擎代码仍须按团队部署配置。文件来源、哈希、实际输出及复现方法见[真实模型验证记录](真实模型验证记录.md)。

## 4. 与团队接口运行

凭据从配置指定的环境变量读取，默认为 `A4_API_KEY`。在当前终端设置团队实际提供的服务凭据后执行；配置文件和命令输出不保存凭据。

```powershell
New-Item -ItemType Directory -Force 'outputs' | Out-Null
.\.venv\Scripts\python.exe -m a4_speech --config config.local.json transcribe --recording-id '实际录音UUID' --idempotency-key '唯一请求标识' --no-save | Out-File -FilePath 'outputs/transcription-result.json' -Encoding utf8
.\.venv\Scripts\python.exe -m a4_speech --config config.local.json save --result-file 'outputs/transcription-result.json' --business-task-id '调用方业务任务标识'
.\.venv\Scripts\python.exe -m a4_speech --config config.local.json read --transcript-id '实际文本UUID'
```

`transcribe --no-save` 依次读取录音及内容、检测语音、核对及登记片段、建立含固定目标和快照的识别任务，再逐段识别。它返回结果 JSON，并尝试只回写处理状态、计数、摘要和快照，不提交文本；`processingRecorded` 表示处理元数据是否已读回核对。调用方留存该结果后，可用 `save --result-file` 独立校验和保存；结果与任务元数据、片段及时间不符时拒绝写入。

只转写时可省略 `--business-task-id`，保存时必须提供；可通过保存命令为未绑定结果补充该标识，不能改绑已有业务任务。省略 `--no-save` 可沿用转写后立即保存的入口，此时必须在转写命令中提供 `--business-task-id`；缺少时在推理前拒绝。无有效结果时不调用文本保存。

保存和读取不加载本地模型。读取命令可显式提供 `--job-id`，它表示 `asr.job` 识别执行任务，与上层业务任务不同；省略时查询该录音的全部 ASR 任务，按片段、原文摘要及创建/执行快照匹配历史来源。唯一匹配时返回相应来源，没有匹配返回 `historyStatus=job_context_required`，多项匹配返回 `ambiguous`。

程序标准输出为 JSON；正常返回处理结果时退出0，其中 `status` 仍可能为 `partial`、`failed` 或 `no_speech`，调用方必须检查结果字段。接口、配置或结果校验等异常退出2。日志写到标准错误，需要留存运行证据时可分别保存两路输出。错误输出不包含服务响应全文和原始凭据。

默认转写并保存入口在保存阶段出错时，错误 JSON 仍保留 `schemaVersion=1`、有效文本、时间、快照、计数及任务关联，不因保存故障丢失已取得的结果。`saveStatus=failed` 表示明确失败，`unconfirmed` 表示结果未确认，`saveConfirmed` 均为 false；可留存该 JSON 供人工核对和独立保存入口校验。已有保存回执时仍只读回核对，不会因再次提供结果文件而自动重发。

## 5. 关键规则与实现边界

### 分段及时间

预查调用 `onlySpeech=false`，同时考虑非语音段冲突；当前契约为非分页列表，兼容带完整分页元数据的扩展响应。完全相同的语音段复用现有ID和序号；同起点异终点或实际重叠均停止。相邻首尾相接合法。只新增不存在的段，固定 `replaceAll=false`。409或传输不明先读回，不盲目重发。

下载后的实际样本时长与录音整数毫秒允许最多50ms的编码/元数据差异；此容忍量不是时间平移。段本身仍必须在录音范围内。仅当样本时长向上取整比录音末尾多1ms时，允许将这一量化尾点收回录音末尾，任意更大越界不会被裁剪掩盖。

绝对时间按录音带时区起点加相对毫秒核对，不再次叠加偏移。校验与结果摘要均按实际 UTC 时刻处理，等价的 `Z`、`+00:00` 和其他时区表示不因字符串不同而被拒绝。不输出推测的VAD得分或ASR置信度。

### 计数、发布与重复执行

处理状态反映识别结果，保存状态反映持久化是否已核对，两者分别判断。

- 正常 VAD 分析确认无语音时返回 `status=no_speech`、`code=NO_SPEECH`，不写空段、不建空 ASR 任务，也不创建空文本。输入异常或模型故障不会映射为无语音。
- 已处理数包括已结束的成功/失败ASR尝试；失败数为其中失败项。第2段失败时计数为2/1，第3段不执行。
- 模型初始化在建ASR任务前独立完成，初始化失败不虚报为片段失败。
- 任一片段识别失败即停止后续识别；此前成功文本及时间、来源保留在结果中，失败段和未处理段分别列出。存在有效成功片段时为 `partial`；没有有效成功片段时为 `failed`，不保存空文本。模型创建后变化仍按模型一致性故障处理。
- 独立保存只接受与已记录任务结果一致的完整有效子集，核对业务任务标识、片段、时间、摘要及快照后提交。保存成功返回 `saveConfirmed=true`、`saveStatus=confirmed`，原 `partial` 状态和计数不变。
- 保存后通过任务和文本读回核对；超时后若实际已保存，可据读回确认成功。
- 完成接口返回400、401、403、404、409、413或422等明确拒绝，且本批文本经逐项查询确认全部不存在时返回 `SAVE_FAILED`。已部分写入、传输超时、5xx及其他无法核对的情况返回 `SAVE_UNCONFIRMED`；本地保存回执无法写入时返回 `SAVE_RECEIPT_FAILED`。组合入口仍返回已取得的完整识别结果，不把存储错误计入 ASR 失败数，也不自动重复写入。
- 已存在文本、人工修改结果或queued/processing片段会阻止新一轮转写，避免覆盖。已有结果通过读取入口查看。

单任务最多包含500个 `segmentIds`；更多目标由编排功能拆分为独立任务。

本地 `outputs/requests/` 保存请求哈希、录音ID和任务ID收据；保存前另按识别任务建立本地保存回执，只用于阻止本机盲目重放，不存第二套业务文本。相同键已有已保存结果时读回核对；未完成、结果不明或收据损坏时停止，不自动接管任务。保存回执已存在时仅尝试读回，不再次发送文本完成请求。相同幂等键限64个可打印ASCII字符；新的人工尝试使用新的键，并先核查已有任务与结果。

当前入口按人工单执行者方式运行。本地回执用于本机重复请求处理，跨机器互斥、任务领取和租约由团队服务协调；待核对事项见下文“团队服务联调”。

### 历史模型

创建时快照位于 `params.a4_10_20.executionSnapshot`；完成时实际快照位于 `stats.a4_10_20.executionSnapshot`。个人扩展JSON还保存固定目标清单、目标录音、本次段数以及原文摘要 `transcriptDigests`。摘要绑定录音、片段、相对时间和原始文本，校验人工修改后的当前文本时仍保留原文含义。独立保存结果另以 `resultDigests` 绑定绝对时刻及语言；新结果的保存和历史读取均核对该摘要，并拒绝识别引擎或业务任务绑定冲突。

保存确认及历史读取支持 `succeeded` 和 `partial` 识别任务，要求目标及有效片段关联匹配、原文摘要匹配、创建与执行快照一致。显式任务没有快照时返回 `not_recorded`；快照或证据不完整时返回 `source_unverified`。只按文本标识读取时，任务列表须完整且录音关联有效；仅唯一可核对的历史来源可用于说明模型。读取旧结果不查询当前引擎版本来补填历史。

当前公共文本详情没有 `jobId`，来源校验使用任务目标、原文摘要和历史快照。因此返回 `sourceJobLinkVerified=false`，表示文本所属任务外键尚待服务端核验。

### 业务任务

业务任务标识通过 `params.a4_10_20.businessTaskId` 或保存时的 `stats.a4_10_20.businessTaskId` 承载，并经任务详情读回。`businessTaskAssociationVerifiedBy=job_metadata_roundtrip` 表示已核对该元数据；`businessTaskForeignKeyVerified=false` 表示公共业务任务的存在性和外键尚未核验。调用方业务任务与 `asr.job` 识别执行任务分别记录。

独立保存沿用现有 `POST /jobs/{jobId}/complete`：转写结束先回写不含文本的处理元数据，保存时再带有效 `transcripts` 调用同一入口，保持原处理状态。两次请求的结构符合现有契约，调用端流程由 HTTP 模拟测试覆盖。

### 团队服务联调

当前验证使用本机模型和模拟 HTTP 接口，尚未连接真实团队服务。联调需提供 A3/A4 地址、服务凭据、可访问的录音 ID，以及与本地模型匹配的启用引擎登记。重点核对以下行为：

- 同一终态任务先回写元数据、后保存文本，能否保持原处理状态并持久保存有效子集。
- 任务 JSON 能否完整保存和读回，业务任务映射与文本所属任务外键是否正确。
- 预查后的并发写入、人工编辑保护、跨接口事务，以及服务重启后的持久化。客户端预查与本地回执提供调用侧检查，服务端幂等、事务和并发控制需在联调中验证。
