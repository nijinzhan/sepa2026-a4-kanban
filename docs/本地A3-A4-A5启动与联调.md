## 输入自己的历史录音

本地适配入口接收能实际解码的 **MP3**，至少 1 秒、单文件不超过 64 MiB。A-4 自身的其他音频格式能力不等于此 A-3 归档入口的输入约定。`.mp3` 后缀下的文字会返回 `422 INVALID_AUDIO`，不能转成语音；这里只需拒收，不需要对这种演示内容做识别适配。超限返回 `413 INPUT_TOO_LARGE`。

把文件复制到 `outputs/local-stack/inbox/`，在另一 PowerShell 终端中读取本地密钥并通知入库：

```powershell
Set-Location 'D:\course_project\现代软件工程\SEPA2026_TeamBlue\李洪'
$localKeys = Get-Content .\outputs\local-stack\keys.local.json -Raw | ConvertFrom-Json
$recordingBody = @{
    inputFile = 'my_recording.mp3'
    startedAt = '2026-11-17T01:00:00Z' # 换成该录音真实 UTC 起点
    stationCode = 'VHHH_APP'
    frequencyMhz = 119.1
    sourceUrl = 'local-archive-replay'
    notify = $true
} | ConvertTo-Json
$ingestResult = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:18050/api/v1/a3/local/ingest' -Headers @{'X-Api-Key'=$localKeys.a3} -ContentType 'application/json' -Body $recordingBody
$ingestResult.recording
$ingestResult.automation
```

先用短录音检查链路。`startedAt` 必须带时区；重复请求须保持同一录音时间、台站、频率、来源及内容。同一台站、同一起点但内容不同返回冲突。当前适配器对历史回放统一记录测试来源标记；正式采集元数据仍需由采集端提供、核对。

`audio_id` 原样写入 `aud.recording.id`；起止点统一 UTC 毫秒，数据库 `duration_ms` 使用实际解码时长，索引的 `duration_s` 保留原 A-3 整秒约定。路径采用分层 POSIX 相对路径；SHA-256 写入 A-5 的 bytea 字段。数据库登记提交后才发自动转写通知；失败后重复提交可继续。索引或音频丢失时，同一已登记内容可恢复原 UUID；已有文件内容不同则拒绝覆盖。

音频下载入口为 `GET /api/v1/a3/recordings/{id}/content`，同样需要 A-3 服务密钥。自动通知使用 `/api/v1/a4/automation/audio-ready`，查询导出服务已自动配好下载地址及其密钥。

## 本地配置和复现条件

- Python：现有 `.venv`，新增依赖为 SQLAlchemy、imageio-ffmpeg；新环境在个人目录安装 `python -m pip install -e ".[postgres,local-integration]"`。
- 模型配置：`config.postgres.local.json`，模型和词表路径须可访问；当前教师模型版本为 `teacher-2025_0706-int8`。
- 数据库配置：`outputs/postgres/runtime.local.json` 的既有 `appDsn`；启动器不重新初始化数据库。
- 状态与证据：`outputs/local-stack/`。密钥随机生成在 `keys.local.json`，端点在 `endpoints.local.json`，各进程日志、原索引、样本、导出及两轮验证记录在同目录。
- 可通过 PowerShell 参数 `-TeamRepo`、`-ModelConfig`、`-Credentials` 指定已有路径。直接运行 Python 启动器还支持 `--state-dir`、`--port`、`--audio`。

本次验证的是历史音频在同一台机器上的功能闭环。实时网络采集、真实 IAM 用户人工修订、长片段导出及主线 A-5 空库容器部署各自仍需对应验收；它们不阻断这里的短录音本地联调。

2026-11-21 主线已提供 V24 修复并在独立临时 PostgreSQL 上验证两个 60 秒含音频导出成功。测试显示：无 V24 时这条 HTTP 路径返回 500，应用 V24 后返回 `succeeded`，两个 PCM WAV 与源 MP3 分别解码出的 60 秒内容相同。详情见[复测报告](../deliverables/测试/2026-11-21-V24长片段含音频导出复测.md)。主线全新库迁移另有 V19 引用 R__01 后续 VHHH 种子的问题，报告中有原样日志和临时测试处理口径。

隔离复测容器与原常驻联调数据库分开。要测试自己的部署，先取得团队数据库维护方确认的迁移修正/执行次序；不要在 `outputs/postgres/runtime.local.json` 指向的现有库上重放全量迁移。
