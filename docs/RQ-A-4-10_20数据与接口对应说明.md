## 3. 两项需求的数据对应

### 3.1 RQ-A-4-10

| 处理环节 | 数据落点与关键字段 | 本人实现要求 |
| --- | --- | --- |
| 获取录音 | `aud.recording.id`、`started_at`、`duration_ms`、`sample_rate_hz`、`audio_channels`、`codec`、`storage_state`及音频访问引用 | 校验录音可读、格式可处理、时长与时间参照有效；通过音频接口取内容，不把数据库文件路径直接当作本机路径 |
| VAD 分段 | `aud.segment.recording_id`、`sequence_no`、`start_ms`、`end_ms` | 片段相对于源录音以毫秒定位，开始早于结束且不超出录音范围；结果与正确录音关联 |
| 时间衔接 | `duration_ms`为生成值；`start_at/end_at`由`aud.fn_segment_derive_timestamps()`按录音起点及偏移生成 | 采用“录音 UTC 起点＋相对毫秒偏移”的统一规则，核对返回时标，避免再次换算造成偏移 |
| 引擎调用 | `asr.engine.code`、`kind`、`model_name`、`version`、`runtime`、`endpoint_url`、`config`等 | 调用启用的 VAD／ASR 引擎；任务创建时固定实际模型版本和参数，后续引擎配置更新不改变旧任务的模型来源 |
| 识别执行 | `asr.job.id`、`engine_code`、`recording_id`、`segment_id`、`status`、`processed_segments`、`failed_segments`、`error_message`等 | 关联本次处理并反馈失败原因；使用已有`partial`及计数字段，统计与发布规则见§6.1 |

`vad_score`、`snr_db`、`confidence`等可空结果字段按实际分析能力和接口要求填写，没有计算结果时保持为空。

### 3.2 RQ-A-4-20

| 业务含义 | 公共数据对应 | 本人实现要求 |
| --- | --- | --- |
| 文本标识与片段关联 | `asr.transcript.id`；`segment_id`必填且唯一 | 一通话段一份当前文本记录；保存时保护已有文本及人工修订 |
| 识别来源 | `job_id → asr.job.id`；`engine_code → asr.engine.code` | 保存并读回识别执行任务和引擎关联；该字段不替代调用方提供的上层业务任务标识 |
| 所属业务任务 | 个人适配使用现有任务`params/stats`扩展JSON | 保存并读回调用方业务任务标识；未绑定结果可在独立保存时补充，禁止改绑。公共映射的核对事项见第6节 |
| 原始与当前文本 | `text_raw`必填；`text_norm`可空；读取结构提供`textRaw/text` | 按写接口明确映射原始结果，保留原始自动转写；规范化或当前文本与原始文本不能混淆 |
| 质量及修订信息 | `language`、`confidence`、`quality_flags`、`revision`、`is_edited`、`review_status`等 | 按接口保存、读取已有信息，保护人工修订 |
| 状态衔接 | `fn_transcript_after_write()`同步通话段识别状态 | 保存后验证文本与通话段状态一致 |
| 完整读取 | `asr.v_transcript_full`提供文本、录音/片段标识、相对和绝对时间等 | 按标识读回并校验；任务、历史模型及处理结果信息通过第5节的来源核对补充 |

需求中的“所属任务”指调用方提供标识的上层业务任务。`asr.transcript.job_id`关联 `asr.job` 的 VAD／ASR 执行任务，记录识别来源。两类关联分别保存、核对；上层业务任务与`ops.job_run`或`anno.workspace`的具体映射见第6节。`job_id/engine_code`虽在数据字典中可空，个人存取流程仍需保留必要来源信息。

## 4. 已有接口与个人调用环节

以下路径来自第1节的现有契约。模块前缀分别为`/api/v1/a3`、`/api/v1/a4`，表中使用相对路径。

| 环节 | 已有接口 | 调用与返回要点 |
| --- | --- | --- |
| 读取录音及内容 | A-3：`GET /recordings/{recordingId}`、`GET /recordings/{recordingId}/content` | 获取元数据和音频；音频流支持完整或范围读取 |
| 登记 VAD 段 | A-3：`POST /recordings/{recordingId}/segments` | 请求含`segments`，片段必填`startMs/endMs`；返回写入统计。采用§6.2的相同片段复用、冲突停止规则；`replaceAll=false`，保护已有分段及下游关联 |
| 获取段标识 | A-3：`GET /recordings/{recordingId}/segments` | 当前写段响应不返回段 ID，应读取段列表并核对对应关系，供后续识别与保存使用 |
| 读取引擎信息 | A-4：`GET /engines` | 可按`kind`及启用状态过滤，读取引擎代码、模型信息和端点 |
| 提交和读取识别任务 | A-4：`POST /jobs`、`GET /jobs/{jobId}`；`GET /jobs`提供列表 | 提交时按契约使用录音或片段标识，返回`Job`；仅按文本标识读取时，以录音和ASR类型读取全部任务页，再核对唯一来源，不猜测最近任务 |
| 回写执行结果并保存文本 | A-4：`POST /jobs/{jobId}/complete` | 转写结束先回写状态、计数及元数据；独立保存再提交有效`transcripts[]`，保持原处理状态。文本项必填`segmentId/text` |
| 保存后读回 | A-4：`GET /segments/{segmentId}/transcript`、`GET /transcripts/{transcriptId}` | 当前完成接口返回`Job`，不直接返回文本 ID；可按段标识读取结果，再取得文本 ID |

现有实现提供 `transcribe --no-save`、`save --result-file` 和 `read --transcript-id` 三个入口；省略 `--no-save` 时转写后立即保存。保存和读取不加载本地模型。转写结束先回写不含文本的处理元数据，独立保存时再提交有效文本。处理状态与保存确认分别返回，部分结果保存后仍为 `partial`。

默认转写并保存入口要求业务任务标识，缺少时在推理前拒绝；只转写可省略，保存时再补充未绑定的标识。保存故障时，默认入口仍返回完整有效结果 JSON，并标明 `saveStatus=failed/unconfirmed`：完成接口明确拒绝且本批文本全部读回为不存在时为 `SAVE_FAILED`；部分写入、超时、5xx或证据不足时为 `SAVE_UNCONFIRMED`；本地保存回执写入失败时为 `SAVE_RECEIPT_FAILED`。识别状态和计数保持原值，文本请求不自动重发。

已有任务状态枚举为`queued/running/succeeded/partial/failed/canceled`。任务状态、片段的`transcript_status`、文本的`review_status`和保存确认分别表示执行进度、片段识别状态、文本审核状态和存储结果。

## 5. 历史模型信息与结果读回

保存记录需追溯实际执行所用模型。“模型历史快照”记录生成某次结果时使用的模型信息。例如，任务J由模型A的版本1生成文本，引擎升级到版本2后，读取任务J仍显示版本1。

《系统概要设计说明书_V0.3》规定任务固定模型版本和参数。个人实现通过现有`asr.job.params/stats`的JSON对象保存快照，沿用创建、完成和任务详情接口。以下嵌套键为个人适配约定：

1. 创建任务时，从服务配置和模型清单生成`params.a4_10_20.executionSnapshot`，记录实际使用的VAD/ASR引擎代码、模型名称、模型版本或文件校验标识及推理参数；使用词典时记录其版本。快照持久化后保持不变，模型版本依据实际文件校验。
2. 执行前核对固定快照与实际模型；固定模型不可用时明确失败。实际执行快照和核对结果写入`stats.a4_10_20.executionSnapshot`及任务关联日志，通过完成接口回写。创建快照与执行记录分别保留，快照元数据与模型推理参数分别处理。
3. 读取历史任务时，使用`GET /jobs/{jobId}`返回的`params/stats`解释模型来源，保留任务生成结果时的模型信息。
4. 以版本1生成并保存结果、升级引擎登记、读取旧任务的流程验证历史一致性。旧任务固定模型不可用时停止执行；旧记录缺少快照时反馈“模型历史未记录”。

个人扩展还记录 `successfulSegmentIds`、`failedSegmentsDetails`、`unprocessedSegmentIds`、原文摘要和结果摘要，用于核对处理结果及独立保存输入。业务任务标识在创建时可写入 `params.a4_10_20.businessTaskId`，也可在独立保存时为未绑定结果补充到 `stats.a4_10_20.businessTaskId`。两者通过任务详情读回核对，返回 `businessTaskAssociationVerifiedBy=job_metadata_roundtrip`、`businessTaskForeignKeyVerified=false`。

读取时可明确提供识别任务标识；仅提供文本标识时，先核对文本、录音、片段和时间，再查询 `GET /jobs?recordingId=...&kind=asr&page=...&pageSize=100` 的全部分页。分页信息、数量、任务录音关联和重复标识必须有效；只在成功或部分成功任务中寻找片段、原文摘要及创建/执行快照唯一匹配的来源。无匹配返回 `job_context_required`，多项匹配返回 `ambiguous`；列表错误明确反馈，不选取最近任务，也不查询当前模型来补写历史。

其他任务创建入口需复用相同的快照与来源证据约定。唯一来源证据匹配后返回 `sourceJobLinkVerified=false`，该字段的依据及联调事项见第6节。

### 6.1 个人计数与结果发布口径

结果发布依据现行需求规格说明书，统计公式及JSON承载方式为个人适配约定。当前实现遇到片段识别失败后停止后续识别，保留并返回此前已成功的结果，不自动重试：

- `processedSegments`为已完成识别尝试的片段数，包括成功段和已明确失败段；`failedSegments`是其中识别失败的段数。因此成功处理段数为`processedSegments-failedSegments`，未处理段不算失败段。
- 在任务开始处理时固定目标片段范围；总数记入`stats.a4_10_20.totalSegments`。公共进度视图按整份录音统计的段数，不一定等于选择部分片段的本次任务总数。
- 存在有效成功片段且仍有失败或未完成片段时，反馈部分成功，返回有效片段及其文本、时间、来源和失败说明。未处理片段单独列出，不计入失败数。
- 部分成功中的有效结果通过关联和时间校验后，可由调用方另行请求保存与读取，保存后仍为`partial`。没有有效成功片段且处理失败时，反馈失败及原因。
- 正常VAD分析确认无有效语音时，反馈`NO_SPEECH`，两个计数均为0，不提交空段、空ASR任务或空文本；处理故障使用相应错误反馈。
- 保存失败或结果未确认时，保留真实识别结果与计数，不把保存错误计入识别失败片段数。未确认时不得报保存成功或自动重复提交；按既有读取能力核对已保存状态。

| 情况 | 本次目标片段数 | processedSegments | failedSegments | 个人反馈与文本提交 |
| --- | --- | --- | --- | --- |
| 3段全部识别成功 | 3 | 3 | 0 | 返回全部有效转写结果；调用方可另行请求保存，保存结果另行确认 |
| 第1段成功、第2段失败、第3段未处理 | 3 | 2 | 1 | 部分成功；返回第1段有效结果，说明第2段失败及第3段未完成；有效结果可另行保存 |
| 第1段失败、后2段未处理 | 3 | 1 | 1 | 处理失败，分别报告失败与未处理片段，无成功文本可保存 |
| 3段识别成功但保存失败 | 3 | 3 | 0 | 保留识别结果，反馈保存失败或结果未确认 |
| VAD正常分析确认没有有效语音 | 0 | 0 | 0 | 无有效语音，映射NO_SPEECH；不提交空段/文本，与分析故障区分 |

上述处理与独立保存规则已在个人代码中实现，验证记录见《代码实现与测试说明》。

保存回执已存在时，只读回核对，不自动重发文本请求。

现有`asr.fn_queue_transcription()`针对已有待识别语音片段创建ASR任务，零片段会报错。VAD确认无语音时，向已有处理任务或调用方反馈结果，跳过ASR建任务步骤。

### 6.2 重复登记片段的个人处理规则

1. 提交前使用`GET /recordings/{recordingId}/segments?onlySpeech=false`读取该录音已有片段；若接口分页则读完所有页，避免默认仅语音筛选漏掉同样受排除约束保护的非语音段。先校验本批片段合法且互不重叠。
2. 同一录音中`startMs/endMs`与已有片段完全一致且`isSpeech`语义一致时，复用既有`segmentId`，跳过新增；保留服务端已有`sequenceNo`和附属信息，不覆盖原段、文本或人工修改。
3. 同起点不同终点、其他实际区间重叠，或显式指定序号已属于另一个片段时，停止登记并记录冲突，不静默合并、改边界或覆盖。
4. 完成本批预查后，只发送确实新增且不冲突的片段，固定`replaceAll=false`；若整批均已存在则不发送空数组，直接使用已有标识。
5. 提交遇到409或连接中断时先重新读取。仅当可验证所需片段确实相同并已存在时复用；仍有冲突则停止，不盲目重试写入。
