## 4. 已有接口与个人调用环节

以下路径来自第1节列出的现有契约。模块前缀分别为`/api/v1/a3`、`/api/v1/a4`，表中使用相对路径。接口路径不能代替需求责任划分。

| 环节 | 已有接口 | 调用与返回要点 |
| --- | --- | --- |
| 读取录音及内容 | A-3：`GET /recordings/{recordingId}`、`GET /recordings/{recordingId}/content` | 获取元数据和音频；音频流支持完整或范围读取 |
| 登记 VAD 段 | A-3：`POST /recordings/{recordingId}/segments` | 请求含`segments`，片段必填`startMs/endMs`；返回写入统计。采用§6.2的相同片段复用、冲突停止规则；`replaceAll=false`，保护已有分段及下游关联 |
| 获取段标识 | A-3：`GET /recordings/{recordingId}/segments` | 当前写段响应不返回段 ID，应读取段列表并核对对应关系，供后续识别与保存使用 |
| 读取引擎信息 | A-4：`GET /engines` | 可按`kind`及启用状态过滤，读取引擎代码、模型信息和端点 |
| 提交和读取识别任务 | A-4：`POST /jobs`、`GET /jobs/{jobId}`；`GET /jobs`提供列表 | 提交时按契约使用录音或片段标识，返回`Job`；与编排负责人衔接，避免双方重复建任务 |
| 回写执行结果并保存文本 | A-4：`POST /jobs/{jobId}/complete` | `status`必填，可带已处理片段数`processedSegments`、失败片段数`failedSegments`、原因及`transcripts[]`；文本项必填`segmentId/text`，可带`textNorm`等 |
| 保存后读回 | A-4：`GET /segments/{segmentId}/transcript`、`GET /transcripts/{transcriptId}` | 当前完成接口返回`Job`，不直接返回文本 ID；可按段标识读取结果，再取得文本 ID |

回写接口在一次调用中同时覆盖“10的执行结果反馈”和“20的文本保存”。这是共用入口，不改变两个需求的完成条件：识别结果成功不等于保存已确认；保存成功也不等于整段录音全部识别成功。

已有任务状态枚举为`queued/running/succeeded/partial/failed/canceled`。任务状态、片段的`transcript_status`、文本的`review_status`及保存是否成功含义不同，不混用。可识别`canceled`不等于本人新增取消入口或调度功能。

人工编辑`PATCH /transcripts/{id}`、词级时标更新和人工时标调整不列入本次个人新增功能。按时间筛选的完整外部查询仍由 RQ-A-4-30 负责；20的按标识读取及存取验证与其协作。

## 5. 历史模型信息与结果读回

个人需求已要求：保存记录可追溯实际执行所用模型，模型更换后旧结果不应被解释为由新模型生成。

“模型历史快照”指保存生成某次结果时实际使用的模型信息。例如，任务J用模型A的版本1生成文本；以后引擎升级到版本2，读取任务J时仍应显示版本1。它不是复制模型文件，也不是要求新增模型训练或管理功能。

《系统概要设计说明书_V0.3》已规定固定模型版本和参数、禁止旧任务静默换模型。现有`asr.job.params/stats`均为JSON对象，创建、完成和任务详情接口也支持这些对象，可用于个人实现保存快照，不需要新增数据库列或HTTP端点。以下嵌套键为本次选定的个人实现约定，不是原数据字典已有的专用字段：

1. 本人创建任务时，由可信的服务配置和模型清单生成`params.a4_10_20.executionSnapshot`，记录实际使用的VAD/ASR引擎代码、模型名称、模型版本或文件校验标识及推理参数；仅在实际使用词典时记录其版本。快照随任务持久化后保持不变，不接受外部任意声明的版本替代真实模型校验。
2. 执行前核对任务固定快照与实际模型；无法提供固定模型时明确失败。将实际执行快照和核对结果写入`stats.a4_10_20.executionSnapshot`及任务关联日志，通过现有完成接口回写；快照元数据不直接透传为模型推理参数。执行后才记录的信息不能冒称“创建时已固定”。
3. 读取已有任务时使用`GET /jobs/{jobId}`返回的`params/stats`解释历史信息，不能用`GET /engines`的当前登记值覆盖。文本与任务关联仍使用已有`asr.transcript.job_id`，不新增另一套业务任务。
4. 验证“模型A版本1生成并保存结果→引擎登记升级→读取旧任务”仍返回版本1；旧任务模型不可用时不能偷偷使用版本2。旧记录没有快照时明确反馈“模型历史未记录”，不补填当前配置冒充历史。

该方案可先在本人10/20的创建、执行和读回适配中完成。若任务由其他负责人的入口创建，创建时固定快照需要该入口复用相同的创建适配；当前文本详情响应也未声明`jobId`，仅有文本标识时不能保证取得所属任务。以上两项涉及公共衔接，不能宣称仅靠个人代码已解决，也不能凭录音编号在多次任务中猜测。具体实现是否原样保存并返回JSON对象及文本关联，仍以接口测试为准。

### 6.1 个人计数与结果发布口径

以下为个人实现选定的统计规则，不是数据字典已经写明的公式：

- `processedSegments`为本次尝试已结束逐段识别的数量，包括成功段和已明确失败段；`failedSegments`是其中识别失败的段数。因此成功处理段数为`processedSegments-failedSegments`，未处理段不算失败段。
- 在任务开始处理时固定目标片段范围；总数记入`stats.a4_10_20.totalSegments`。公共进度视图按整份录音统计的段数，不一定等于选择部分片段的本次任务总数。
- 按用户指定的概要设计，个人处理遇到片段识别失败即停止本次尝试，反馈`failed`及失败原因，不提交部分成功的`transcripts`。全部片段成功后一次提交有效文本；保存响应未确认时先读回核对，不能标记完成。
- 公共枚举保留`partial`以兼容已有接口，但个人这条失败即停止的处理路径不产生`partial`。状态为`failed`不代表`failedSegments`一定大于0：模型加载、预处理或保存失败可能没有失败的识别片段。
- VAD无有效语音时，按`NO_SPEECH`反馈`failed`，两个计数均为0。保存失败时保留真实识别计数，不把保存错误虚报成所有片段识别失败。

| 情况 | 本次目标片段数 | processedSegments | failedSegments | 个人反馈与文本提交 |
| --- | --- | --- | --- | --- |
| 3段全部识别成功 | 3 | 3 | 0 | 提交全部文本，确认保存后完成 |
| 第1段成功、第2段失败，停止第3段 | 3 | 2 | 1 | failed，不提交部分文本 |
| 3段识别成功但保存失败 | 3 | 3 | 0 | 反馈保存失败或结果未确认，不能声称已持久化 |
| VAD没有有效语音 | 0 | 0 | 0 | failed，原因NO_SPEECH，不提交空段/文本 |

上述规则约束个人提交行为。现有段登记与文本完成为两个HTTP调用，不能据此宣称已经具备“片段＋文本＋任务”跨接口的原子事务；全量文本与任务状态是否同事务提交须通过公共完成接口验证。个人需求规格说明书同步采用“本次失败不发布部分正式文本、保存和识别分别确认”的业务口径，具体字段和公式留在本文。

无语音时反馈原因不代表必须凭空创建一条ASR任务。现有`asr.fn_queue_transcription()`只对已有待识别语音片段建ASR任务，零片段会报错；VAD阶段无语音应反馈给其已有处理任务或调用方，不调用该函数伪造空ASR任务，不把这一函数误说为支持“先建ASR任务再标无语音”。

### 6.2 重复登记片段的个人处理规则

1. 提交前使用`GET /recordings/{recordingId}/segments?onlySpeech=false`读取该录音已有片段；若接口分页则读完所有页，避免默认仅语音筛选漏掉同样受排除约束保护的非语音段。先校验本批片段合法且互不重叠。
2. 同一录音中`startMs/endMs`与已有片段完全一致且`isSpeech`语义一致时，复用既有`segmentId`，跳过新增；保留服务端已有`sequenceNo`和附属信息，不覆盖原段、文本或人工修改。
3. 同起点不同终点、其他实际区间重叠，或显式指定序号已属于另一个片段时，停止登记并记录冲突，不静默合并、改边界或覆盖。
4. 完成本批预查后，只发送确实新增且不冲突的片段，固定`replaceAll=false`；若整批均已存在则不发送空数组，直接使用已有标识。
5. 提交遇到409或连接中断时先重新读取。仅当可验证所需片段确实相同并已存在时复用；仍有冲突则停止，不盲目重试写入。该调用端核对不能代替服务端锁或数据库排除约束。

## 8. 范围限制
