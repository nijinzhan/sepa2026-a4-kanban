# V24 导出修正复测计划

用户已授权先验证主仓库 V24，并了解抽听及长音频测试方法。本轮执行范围为 V24 修正前后 SQL 和 HTTP 含音频导出；长音频资源测试在说明中给出方法，不扩展执行范围。

使用主仓库固定 Git 快照，所有提取文件、配置、凭据、音频和测试产物放在个人 ignored outputs。新建独立 PostgreSQL 16 容器，使用临时数据目录，不挂既有数据库卷；不修改同学源码或既有联调数据库。按原 bootstrap 和 psql 迁移执行器，先完成 V1—V23 与种子，复现旧函数，再通过同一执行器应用 V24。

- [ ] 启动 Docker，核对缓存镜像及隔离资源配置；提取主仓库迁移、原执行器和查询导出源码并记录哈希。
- [ ] 在空库原样执行主线 V1—V23 与种子；建立专用录音/片段夹具，复现旧函数 64 kbps/34 秒及 32 kbps/68 秒的溢出。
- [ ] 通过原执行器增量执行 V24，核对迁移账本、整数边界、includeAudio=false、显式 segment_ids 和重复构建。
- [ ] 对同一真实历史 MP3 的 120 秒音频切片，建立专用 60 秒导出片段；经个人 A-3 下载和原样于天名 HTTP 服务完成 ZIP 导出，检查 WAV 时长、采样率、内容对应及哈希；夹具文本明确不是 ASR 结果。
- [ ] 停止本次服务及临时容器，记录修正前后结果和独立库来源；输出 Markdown 报告，说明轻量抽听的用途及长音频资源测试步骤。

成功条件：旧版稳定复现 SQLSTATE 22003；V24 后相同输入和长片段 HTTP 导出成功，audio_bytes 估值正确、实际音频切片与源录音时间对应；未经本轮验证的 ASR 质量、长音频性能和正式共享环境部署保持原状态。
