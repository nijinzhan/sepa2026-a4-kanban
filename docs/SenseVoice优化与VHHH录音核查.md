## 2. 能否使用现有其他模型改进 SenseVoice

**可行的离线路线是：已有 XLS-R/Whisper 产生转写草稿与分歧提示，人工听音复核，形成新的领域训练数据，再微调 SenseVoice 本身。** XLS-R、Whisper 的权重不能作为 SenseVoice 权重直接替换；仅在旁边运行其他模型，也不会让已部署 SenseVoice 自动学习。

建议以现有 ATC 微调 XLS-R 为主要辅助转写器，Whisper 为交叉检查来源，重点人工核对呼号、数字、航路点、漏词与串段。模型一致不等于人工真值；不同模型也可能有相同错误。已知 Whisper 检查点与原49条中的部分数据存在训练成员重合，因此不能拿它在该集合上的结果作为独立泛化证据。

当前本地 SenseVoice 的 `model.int8.onnx` 是部署推理文件。标准微调路线需准备可训练的 SenseVoice 原始检查点、配置和词表，使用官方训练流程；这不要求把线上识别引擎换成 XLS-R/Whisper。官方 FunASR 文档提供 SenseVoice 的 `finetune.sh` 与专用训练数据格式；微调后还需单独验证导出 ONNX、CPU 推理及量化前后的一致性。不能承诺训练后一定优于原权重，也不能把其他模型输出直接登记成人工参考。

本次未启动权重训练，未增加训练依赖，未变更线上模型身份或引擎登记。离线训练可以使用本机 GPU，最终仍以符合现有接口的 CPU SenseVoice 模型交付；具体训练配置的显存占用需要实测。

官方依据：

- [FunASR 训练、数据与导出说明](https://modelscope.github.io/FunASR/training.html)
- [SenseVoice 官方项目](https://github.com/FunAudioLLM/SenseVoice)

## 5. 建议的下一步顺序

1. **先完成小规模 VHHH 参照集**：从上述北塔台、南地面、离场来源开始，确认可获取的音频、字幕/人工听写、来源与使用条件；逐段记录来源、音频哈希、相对起止、英文参考、校对状态、是否剪辑。没有连续原音频和明确时区就不填写推测的原始 UTC。
2. **用现有 XLS-R、Whisper 辅助复核**：保留各模型原始输出，人工检查分歧，尤其是数字、呼号与术语。已有人类参考的数据优先使用经核验的参考，不用模型标签覆盖它。
3. **先划分再训练**：按来源录音/日期划分训练、验证与最终测试；不将同一录音相邻片段随机拆散，不把现有49条诊断集同时作为训练集与独立最终成绩。
4. **再做 SenseVoice 的最小微调试验**：准备原始可训练检查点与官方数据格式，先小批量运行、核对可训练参数及损失，再评估是否扩大；导出后比较 Python 与 sherpa-onnx CPU 输出。
5. **由质量收益决定是否替换权重**：统一评分，比较英语 WER、数字/呼号错误、遗漏、耗时与导出回归；质量未提升时保留原权重并记录结果。真实团队登记与接口联调在对方服务具备时继续，不作为当前数据和模型工作的阻塞项。

## 7. C15 视频人工字幕的获取方式与时间轴核验

2026-10-23，通过正常浏览器打开上述第15期视频，确认其 `aid=23571520`、`cid=39345110`，页面媒体时长为309秒（5分09秒）。播放器正常发出的响应 `code=0`、`need_login_subtitle=false`，其中 `subtitle.subtitles=[]`；页面初始数据的字幕列表和 HTML 视频文本轨道也为空。这只能说明本次页面没有提供独立字幕轨道，不能扩大为作者没有字幕源文件。

在视频46.234767秒处，将 HTML 视频像素直接绘制到画布，英文行与中文翻译仍保留在原始帧中，确认有烧录在画面里的双语硬字幕。预览为640×360，仅用于确定字幕形式，不是完整字幕提取。核查证据保存在 `outputs/vhhh-c15-20261023/subtitle-inspection.json` 与 `video-subtitle-preview.png`；摘要不保留请求头、账户或网络地址信息。

建议按以下顺序获取人工参考：

1. **原字幕文件优先**：如能向作者取得本期 `.ass` / `.srt`，保留原件、来源与作者说明；这里尚未取得，也没有代用户向作者发送消息。原文件通常能保留字幕文字及视频时间轴，但仍需听音校对和确认与原MP3的对应关系。
2. **现有硬字幕可用 OCR 提取**：取得可正常获取的视频文件后，选择英文字幕区域进行画面文字识别，按画面变化抽帧、合并重复文字，导出带视频相对时间的 SRT。先处理一小段检查文字和漏行，再扩大；使用独立工具目录/环境，不修改A-4推理依赖。本次未部署OCR工具或执行批量识别；尝试核查外部工具仓库时遇到连接重置/导航超时，因此不将具体工具的版本和功能写为已验证。
3. **人工逐句复核**：保留未改动的 OCR 草稿，再对照声音检查英文、呼号、数字、遗漏和字幕轴。中文只作为翻译参考；显示用三字码、说话方标记、注释等不得不经检查直接算作英语逐字转写。OCR 结果在完成复核前标为 `reviewed=false`，不能作为已经验证的人工真值。
4. **先视频轴，再原MP3轴**：视频309秒，而下载MP3实际解码714.60575秒；作者也说明视频做过降噪和静音删减。因此不能将视频SRT时间直接复制给MP3，也不能只加一个未经验证的固定偏移。若评测视频音轨，可先以该音轨与复核字幕成对建小集；若评测原MP3，需逐段核对声音对应、记录原音频起止，并检查开头/中间/结尾及剪辑处。强制对齐只能辅助定位，不能代替对字幕正确性的核查。

建议分开保留 `video.ocr.raw.srt`（画面识别草稿）、`video.reference.reviewed.srt`（听音复核、视频时间轴）和 `original.reference.reviewed.jsonl`（原MP3时间轴的已核对片段）。逐条记录源文件哈希、原始字幕、评分用逐字文本、复核状态和时间轴来源。以上为目标交付物命名建议，本次没有创建空字幕文件，也没有声称已经完成全文OCR、逐句校对或音频对齐。
